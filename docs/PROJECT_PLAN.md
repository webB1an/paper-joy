# PaperJoy 产品与开发方案

版本日期：2026-11-05。依据用户提供的调研聊天、当前需求与两个参考项目的只读代码检查制定。

## 已确定的产品方向

暂用名称「纸趣儿童打印素材 · PaperJoy」。服务家长，首期以约 4—7 岁的纸上活动为选材方向，具体年龄只是使用建议，逐包经过试用调整。主打 A4、黑白省墨、预览清楚、网盘领取和简单打印说明。

第一版使用百度＋夸克网盘，提供免费领取和广告。暂不做支付、在线 AI 生成、儿童账号、用户上传、社区、打印机连接和在线 PDF 编辑器。

## 用户流程与页面

1. 从微信搜索、分享卡片或首页进入，游客可以看公开内容。
2. 按主题、年龄建议、难度、页数等筛选，或搜索「动物涂色打印」等具体用途。
3. 详情展示封面、部分内页、总页数、纸张、彩色/黑白、答案、所需材料和打印说明。
4. 点击领取，选百度或夸克，复制链接与提取码，按指引到网盘保存和获取文件。
5. 收藏或查看领取记录，需要账号时再进行微信登录；失效链接可反馈。

底部导航建议为「发现 / 分类 / 收藏 / 我的」。搜索结果、专题、详情、领取说明和反馈为独立页面。详情使用稳定 ID，可从搜索或分享直接打开，不依赖上一个页面状态。

广告策略：常规免费素材保留可用的领取入口。广告能力开通后，为明确标注的额外合集提供自愿激励广告入口；取消观看不发额外权益；无广告填充或广告失败时说明状态并提供普通免费资源入口。未配置广告位时关闭相关界面。实际奖励规则按平台能力接入，不把客户端任意布尔值当作可信发奖证明。

领取页明确说明文件通过网盘交付，不宣传小程序直连打印机。复制链接、访问短链、实际转存、最终打印是不同事件；只有能取得真实平台数据时才计入转存或收益。

## 后台与内容生产

后台首期包括资源、分类、专题、预览图、网盘链接、授权台账、导入批次、失效反馈和基础数据。支持草稿、待检查、已发布、已下架，批量导入需要可重试且不重复创建资源。

内容流程：

本地选材与许可记录 → A4 排版和答案生成 → 自动检查与人工审稿 → 实际试印 → 制作压缩预览 → 上传两个网盘 → 导入目录和链接 → 后台检查 → 发布。

网盘自动上传先核对旧项目现有接口和授权能力；手工上传并录入链接也应能独立完成首版运营，避免整个项目被第三方接口阻塞。

## 技术方案

| 部分 | 方案 | 理由 |
|---|---|---|
| 小程序 | 微信原生小程序，TypeScript，原生页面 | 延续已有项目结构，独立详情页便于分享和搜索 |
| API | NestJS + Prisma + MySQL | 与两个参考项目技术栈一致，减少迁移成本 |
| 管理后台 | React + Vite + Ant Design | 复用已有资源管理交互和批次运营经验 |
| 后台任务 | MySQL 任务表，单进程限并发 | 首期减少额外常驻服务；长任务可恢复 |
| 素材加工 | 本地脚本和桌面工作流 | PDF 排版、压缩、打包不占服务器算力 |
| 部署 | Nginx + 单 API 进程 + MySQL | 管理端静态文件由 Nginx 托管，本地或 CI 构建 |

数据库暂定名称 `paper_joy`，用户使用已指定的 `paper-joy`，仅授予本项目数据库权限。部署前检查服务器已有 MySQL 的版本、内存占用和备份方式，再决定复用实例或单独安装；不假定服务器为空。

建议代码目录为 `apps/miniprogram`、`apps/api`、`apps/admin`、`packages/shared`、`tools/content` 和 `deploy`。当前先维护策划与素材，实际脚手架在实现阶段建立。

核心数据表：资源、分类、标签、专题、资源预览、网盘链接、来源许可、导入批次、任务、用户、收藏、领取事件、广告权益、反馈、后台审计。资源记录至少包含 slug/ID、标题、主题、年龄建议、难度、页数、纸张、颜色、答案、版本、内容哈希和发布状态。

## 实施顺序与验收

| 阶段 | 交付 | 完成条件 |
|---|---|---|
| 0 准备 | 范围、Logo 初稿、视觉规范、素材来源记录 | 可查看方案和素材，不假定账号已开通 |
| 1 单条链路 | 独立工程、首页、详情、后台、一个示范包 | 本地导入后可预览，两个网盘链接可领取 |
| 2 内容与运营 | 搜索分类、收藏、专题、批次导入、失效反馈 | 3 个主题包可按同一流程上架和修正 |
| 3 广告与体验 | 配置化广告、领取记录、设备兼容 | 完整/取消/失败观看路径一致，iOS/安卓真机可用 |
| 4 部署与上线 | 数据库、域名 HTTPS、备份恢复、提交审核 | 域名和真实 AppID 联调，已有服务不受影响，数据可恢复 |

先用一份完整 PDF 验证从素材制作到家长领取、试印的闭环，再扩库。上线首批以三个主题包为目标：动物涂色 10—20 页；分级迷宫约 20 页活动加答案；控笔与奖励表 10—20 页。这是制作目标，不是已经完成的数量。

质量检查集中在：迷宫有解且答案对应、PDF A4 尺寸与字体正常、源文件和预览一致、授权可追溯、链接无效可下架、导入可重试、后台接口鉴权、密钥不进入前端、内存和磁盘用量可控。

完成每个阶段后更新仓库；实现后运行对应构建、核心流程测试和有代表性的真机验证。服务器承载能力以压测和实际进程占用为准，不能仅凭 2 核 2G 推定并发能力。
